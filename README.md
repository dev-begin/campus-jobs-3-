# 🎓 Campus Jobs — แพลตฟอร์มจับคู่งานพาร์ทไทม์ในมหาวิทยาลัย

## 1) Business Understanding

**ลูกค้า (กลุ่มผู้ใช้จริง)**
- **นักศึกษา** — ต้องการรายได้เสริมที่ยืดหยุ่นกับตารางเรียน ใกล้มหาวิทยาลัย
- **ผู้ประกอบการรอบมหาวิทยาลัย / หน่วยงานในมหาวิทยาลัย** — ร้านอาหาร ร้านกาแฟ ศูนย์คอมพิวเตอร์ ห้องสมุด ชมรม ที่ต้องการคนช่วยงานชั่วคราว

**ปัญหา (Pain Point)**
- นักศึกษา: หางานจากกลุ่ม Facebook/LINE/ป้ายประกาศ ข้อมูลกระจัดกระจาย ไม่รู้ว่ายังเปิดรับอยู่ไหม ค่าตอบแทนไม่ชัดเจน และไม่รู้ผลการสมัคร
- ผู้ประกอบการ: ประกาศแล้วหาคนที่เวลาว่างตรงกันยาก คัดกรองผู้สมัครผ่านแชตวุ่นวาย

**วิธีแก้**
- ศูนย์รวมประกาศงานเฉพาะนักศึกษา ค้นหา/กรองตามหมวดหมู่ ค่าตอบแทน คำค้น
- สมัครงานในระบบ + ติดตามสถานะ (รอพิจารณา / ผ่าน / ไม่ผ่าน) ผู้ประกอบการจัดการผู้สมัครได้ในที่เดียว

## 2) สถาปัตยกรรม
- Frontend: HTML/CSS/JavaScript (fetch + Partial Render ไม่รีโหลดหน้า)
- Backend: Node.js + Express (RESTful API)
- Database: SQL (SQLite เพื่อรันง่ายตอนเดโม — โครงสร้างตารางย้ายไป PostgreSQL ได้ เพราะความสัมพันธ์ users–jobs–applications ชัดเจนและต้องการ JOIN)
- Auth: JWT (รหัสผ่านเข้ารหัสด้วย bcrypt) + role: student / employer

| Method | Endpoint | หน้าที่ | สิทธิ์ |
|---|---|---|---|
| POST | /api/auth/register | สมัครสมาชิก | ทุกคน |
| POST | /api/auth/login | เข้าสู่ระบบ ได้ JWT | ทุกคน |
| GET | /api/jobs?category=&pay_min=&q=&date=&time_from=&time_to= | ค้นหา/กรองงาน | ทุกคน |
| GET | /api/jobs/:id | รายละเอียดงาน | ทุกคน |
| POST | /api/jobs | ลงประกาศ | employer |
| PUT/DELETE | /api/jobs/:id | แก้ไข/ปิดรับ/ลบ (เฉพาะเจ้าของ) | employer |
| GET | /api/jobs/mine | งานของฉัน | employer |
| POST | /api/jobs/:id/apply | สมัครงาน | student |
| GET | /api/applications | ใบสมัครของฉัน / ผู้สมัครงานของฉัน | ล็อกอิน |
| GET | /api/applications/income | รายได้รวมของนักศึกษา | student |
| PUT | /api/applications/:id/status | เปลี่ยนสถานะใบสมัคร | employer เจ้าของงาน |

**ความปลอดภัย:** parameterized query (กัน SQL Injection), escape ก่อนแสดงผล (กัน XSS), bcrypt hash, JWT หมดอายุ 2 ชม., ตรวจสิทธิ์ความเป็นเจ้าของทุก endpoint ที่แก้ข้อมูล

## 4) KPI
- เวลาตอบสนองการค้นหา (แสดงบนหน้าเว็บ เช่น "พบ 3 งาน (ตอบสนอง 12 ms)")
- จำนวนงานที่ลงประกาศ / จำนวนใบสมัคร / สัดส่วนใบสมัครที่ได้รับการตอบกลับ
- เทสต์อัตโนมัติผ่านครบ (`npm test`)

## 5) วิธีรัน
ต้องใช้ Node.js 22.13 ขึ้นไป (แนะนำรุ่น LTS เช่น 24.x) — ฐานข้อมูลใช้โมดูล node:sqlite ที่มากับ Node จึงไม่ต้องคอมไพล์หรือติดตั้งเครื่องมือเพิ่ม

```bash
npm install
npm run seed     # ข้อมูลตัวอย่าง (ครั้งแรก)
npm start        # เปิด http://localhost:3000
npm test         # ทดสอบ API
```
บัญชีเดโม (รหัสผ่าน 123456): นักศึกษา `kk@demo.com` · ผู้ประกอบการ `cafe@demo.com`

## 6) สคริปต์เดโม (3-4 นาที)
1. เปิดหน้าแรก (ไม่ต้องล็อกอิน) → พิมพ์ค้นหา/เลือกหมวด/ใส่ค่าตอบแทนขั้นต่ำ → รายการเปลี่ยนทันทีไม่รีโหลด + โชว์เวลาตอบสนอง
2. ล็อกอิน `kk@demo.com` → สมัครงาน 1 ตำแหน่ง → แท็บ "ใบสมัครของฉัน" เห็นสถานะ "รอพิจารณา"
3. ออกแล้วล็อกอิน `cafe@demo.com` → "จัดการงาน" → เห็นผู้สมัคร กด "รับ"
4. กลับไปล็อกอินนักศึกษา → สถานะเปลี่ยนเป็น "ผ่านการคัดเลือก"
5. โชว์ความปลอดภัย: ลองสมัครซ้ำ (409), นักศึกษาลงประกาศไม่ได้ (403), รัน `npm test`

## 7) ข้อมูลตัวอย่าง และช่องทางติดต่อ
- ร้านและงานที่เห็นตอนรัน `npm run seed` เป็น **ข้อมูลสมมติสำหรับเดโม** ไม่ใช่งานที่เปิดรับจริง เบอร์/LINE เป็นค่าสมมติทั้งหมด
- ใช้งานจริง: ให้ผู้ประกอบการสมัครสมาชิกและลงประกาศเอง (ต้องกรอกเบอร์หรือ LINE อย่างน้อย 1 ช่องทาง)
- ช่องทางติดต่อของงาน เห็นได้เฉพาะผู้ที่ล็อกอินแล้ว (รายการสาธารณะไม่ส่งเบอร์ออกไป) ส่วนผู้ประกอบการเห็นเบอร์/LINE ของผู้สมัครในหน้าจัดการงาน
- กด "ดูรายละเอียด / ติดต่อ" ที่การ์ดงานเพื่อเปิดหน้ารายละเอียด (คุณสมบัติ สวัสดิการ ช่องทางติดต่อ) และสมัครงานได้จากหน้านั้น
- รีเซ็ตข้อมูลเดโม: หยุดเซิร์ฟเวอร์ (Ctrl+C) แล้วรัน `npm run reset`
